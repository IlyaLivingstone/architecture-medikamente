# Задание 5. Разработка cutover-плана

Задача — выбрать одну из трёх стратегий миграции и на её основе разработать план перехода:
этапы, сроки, ответственные, риски и порядок действий при проблемах.

## Выбранная стратегия

**Branch by Abstraction.** Обоснование коротко: у «Медикаменте» нет работающей старой системы
в том смысле, в котором её требует Parallel Run — регистрация и медкарты ведутся в Excel-файлах
и сканах, которые не обрабатывают запросы. Запускать параллельно нечего, сверять пришлось бы
ответы системы, которой не существует. Branch by Abstraction позволяет закрыть адаптерами
файлы и 1С, переключать домены по одному правилами маршрутизации и откатывать изменение за
минуты, а не за часы.

Parallel Run при этом не отброшен: он применяется как приём внутри стратегии — на доменах
«платежи» и «склад с бухгалтерией», где 1С действительно работает и есть что сверять.

High-Level Design используется там, где он уместен: для аналитического контура, у которого
нет легаси и который можно спроектировать целиком.

## Как устроен план

Пять стадий, как требует задание: подготовка, тестирование, реализация, мониторинг, откат.
Общий горизонт — около 8 месяцев, из них 10 недель занимает само переключение доменов.
Домены переключаются в порядке от наименее рискованного к наиболее: сначала аналитика (легаси
за ней нет), последними — склад и бухгалтерия, где 1С является источником правды до нулевых
расхождений в сверке.

Переключение делается не выключателем, а правилами маршрутизации за слоем абстракции:
10% трафика, затем 50%, затем 100%. Откат — возврат правила, а не откат данных.
