# Задание 3. Оценка Data Encryption at Rest and In Transit

Задача — разработать стратегию защиты данных целиком: определить, что защищать, чем, как это
контролировать и что для этого нужно закупить и развернуть.

## Логика решения

**Классификация.** Данные разложены по двум осям: чувствительность (особый, высокий,
средний, внутренний) и состояние (в покое, в передаче, в использовании). Уровни заданы не по
«важности вообще», а по последствиям утечки: медицинские данные бьют по человеку, поэтому
они на верхнем уровне, а финансовые — на уровень ниже, хотя требования регуляторов по ним
жёстче.

**Инструменты.** Разные состояния требуют разных средств, и они не заменяют друг друга:
шифрование диска не защищает трафик, TLS не защищает данные в памяти. Поэтому в
[02_Инструменты_защиты.md](02_Инструменты_защиты.md) средства сгруппированы по состояниям, а
управление ключами вынесено отдельно — без него шифрование не работает.

**Контроль.** Раз в клинике всего три IT-специалиста, ставка сделана на автоматику: аудит,
SIEM с правилами корреляции, DLP, проверки в сборочном конвейере и метрики, по которым видно,
что защита действительно включена.

**Этапность.** Реестр разделён на минимальный набор для MVP (портал пациента и начало
миграции) и целевой набор — то, что можно внедрить после, без блокировки запуска.
